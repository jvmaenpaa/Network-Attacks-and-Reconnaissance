# a) Take a look at the RFID products you use, and think how how well you are protected against RFID snooping?

Products I use are my phone, smartwatch and debit/credit cards (so NFC pretty much). Phone is what I use the most since it has pretty much everything I need (google pay, public transit card, gym membership card, student ID etc.).
When it comes to protection from RFID snooping I don´t have anything fancy set in place for protection. I just have PINs and biometrics set on my phone and watch then of course PIN on my payment cards and I have also set quite strict transaction limits in case I lose my cards or they gets skimmed. I also check my banks statements every once in a while.

In general I'm not that worried of RFID snooping since I mostly use NFC for paying and capturing those signals is extremely difficult and each transaction use dynamic one-time codes so the data cant be reused (at least not as easily for what I understood).

# b) Familiarize yourself with the structure of APDU commands

"Application protocol data unit (APDU) is the message format for all communication between a smart card and its host (the reader or terminal)". The host initializes the communication by sending a command APDU, which can be a request for information, request to perform an action or computation, or instruction to change something on the card. Then the card responses with a
response APDU which includes data, if there is any, and a status word.

# c) Research and share any interesting news you found regarding RFID hacking.

I found [this](https://thehackernews.com/2024/03/dormakaba-locks-used-in-millions-of.html) news article from 2024 that tells about hotel locks for which key cards could be forged. The article said that in 2022 group of researchers found a vulnerability in Dormakaba's Saflok electronic RFID locks. This vulnerability could be exploited by reading a certain code from a keycard and make a pair of forged ones which could be used to reprogram the lock and open it. The code could be read even from a expired key card.
Then the researcher took this a notch further and reverse engineered the device used to program the locks and by doing that they were able to make a master keycard that could open any door which used these locks that has the vulnerability.
Full technical details about the vulnerabilities haven't been made public but there was a mention in the article that some locks had been in use since the 1980s which might be part of the problem (weak/ outdated cryptography).
